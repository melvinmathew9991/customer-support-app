## Bugs found and their status

**Bug 1 (Critical, FIXED) - identification accepted garbage/unmatched input
as a valid, fabricated user.** `ident-003` (non-identifying input "hey
there") and `ident-004` (a genuinely unknown email) both produced a
schema-valid but fabricated `UserProfile` instead of failing - e.g. *"Hi,
I am your Shopify Agent... you have the subscription"* for blank input,
and a fabricated user named "nobody" for an unmatched email. `ident-005`
(a real user with no subscription record in the mock DB) produced the
literal string `"null"` as a displayed subscription. Root cause:
`with_structured_output` constrains the *shape* of the extraction, not
whether the model is honest about finding nothing. **Fix:**
`UserInfoChainBasedEdge._parse` (`agents/support.py`) now deterministically
checks the raw tool-call observations before ever asking the model to
extract a `UserProfile` - if `user_info_db_search` was never called, or
returned an empty match, or `user_subscription_db_search` returned an
empty match, it raises immediately instead of attempting extraction.
Also hardened `AuthenticatedUserNode.greeting_message`/`_get_retriever`
(same file) to fail safe with a plain message instead of crashing if a
non-`UserProfile` ever reaches this node (the pre-existing retry-exhaustion
path, which was reachable in theory before this fix but never observed
because bad input was always succeeding via fabrication). Re-verified:
`ident-001` (control, still passes), `ident-003`, `ident-004`, `ident-005`
all now correctly fail safe with a retry/error message instead of
fabricating.

**Bug 2 (High, NOT fixed) - call-me ticketing crashes without the optional
`audio` extra installed.** `call-002` triggered `CallCustomerEdge`
correctly, but `CallCustomerNode`'s tool does an unconditional
`import whisper` (`tools/audio_transcribe.py:14`), which isn't part of the
default `pip install -e ".[dev]"`. Phase 4 is marked "Done" in
`Phases.md`, but the flow it describes cannot complete out of the box.
Not fixed in this session - needs a decision (make `audio` a hard
dependency, or make the tool degrade gracefully / skip the transcription
step when whisper isn't installed) before fixing.

**Bug 3 (Medium, NOT fixed) - confirmed hallucination on the tier-crossing
adversarial case, not tier-leakage.** `rag-adv-001`: a free user asking
about multi-location support got told "Yes, you can set up multiple store
locations" - factually wrong for their tier. Verified directly that the
free-tier retriever itself only returned `assets/free/*` chunks (no
leakage in retrieval/tier-selection logic), and the top chunk correctly
states single-location-only for free - the model was given the right
grounded context and contradicted it anyway. This is exactly what the
hallucination-rate metric (`docs/eval/Metrics.md` #5) exists to catch.
Not fixed here - a prompting or model-strength question, out of scope for
a one-off patch.

**Bug 4 (Medium, already logged, NOT fixed) - callback-intent recall is
genuinely poor.** `call-001` (identical phrasing already flagged as flaky
during the Sprint 0 audit) failed to trigger again this run. Consistent
with the non-determinism already recorded in `docs/Sprints.md`'s
out-of-band entry - this baseline run adds a second confirmed data point,
not a new finding.

## Grading note

`rag-paid-001` (paid user, locations question) got *"The maximum number
of locations that you can have depends on your plan"* - true and grounded
in the retrieved paid-tier content, but it doesn't state the expected key
fact ("you can have multiple locations") as directly as hoped. Not scored
as a failure since nothing is fabricated, but flags a rubric question for
the harness: hallucination grading needs to distinguish "wrong/fabricated"
from "technically true but doesn't answer what was asked" - the latter is
a quality issue, not a hallucination.
